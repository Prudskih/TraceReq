# Результаты тестирования

Проверка выполнена 18 ноября 2026 на Windows, Python 3.12.4 в `.venv-test`.

## Результат

- pytest: 50 passed, 1 warning, 17.98 секунды.
- pytest-cov: 95% суммарного покрытия строк и ветвлений; 984 оператора, 120 ветвей.
- Ruff: All checks passed.
- mypy: Success, no issues found in 41 source files.

Версии основных зависимостей этого прогона: FastAPI 0.163.2, Starlette 1.10.0,
SQLAlchemy 2.0.58, Pydantic 2.14.3, pytest 9.2.0, httpx 0.28.1.

## Набор проверок

- `tests/test_api.py`: CRUD, уникальность проектов, входная валидация, история,
  запрет доступа к требованиям другого проекта, связи, матрица, удаление зависимых
  строк, ответы 404, HTML, статические файлы и OpenAPI.
- `tests/test_documents.py`: импорт настоящего DOCX, маркеры `<конец>`/`<end>`,
  история импорта, повреждённые/пустые/слишком большие файлы, разбор реальных XLSX,
  значения матрицы и сохранение пользовательских строк как текста вместо формул.
- `tests/test_transactions.py`: отказ на второй вставке импорта и сбои записи истории
  при создании/обновлении. Проверяется отсутствие частичных изменений после rollback
  и возможность выполнять последующие запросы.
- `tests/test_database.py`: старый SQL-формат таблиц и сохранённые Enum читаются без
  миграции; запуск не меняет содержимое существующего файла; SQLite проверяет FK.
- `tests/test_server.py`: установленный пакет запускается через `python -m tracereq`
  отдельным процессом, обслуживает реальные HTTP-запросы и завершает работу после теста.

## Исправления, обнаруженные проверками

1. Приложение не импортировалось: `RequirementService.list` перекрывал встроенный
   тип `list` в аннотации метода `history`. Метод переименован в `list_with_links`.
   Импорт приложения и сценарий истории теперь проходят через тесты.
2. Аннотация XLSX-строки заменена на `Sequence[str | int]`, чтобы корректно принимать
   последовательности строк; OpenAPI-описание XLSX получило явную совместимую аннотацию.
3. Исправлены порядок импортов и форматирование по настройкам проекта.
   Для bootstrap-скрипта сохранена намеренная проверка минимальной версии Python.

## Окружение и ограничения

Системный `python` указывает на Python 3.10.6, поэтому использован установленный
Python 3.12.4. Для запуска нужно активировать подходящее окружение или указывать
его интерпретатор явно. Первые попытки тестирования в песочнице зависали внутри
Windows `socketpair`, до выполнения кода приложения; успешный прогон выполнен
с разрешёнными локальными сокетами.

Рабочих файлов SQLite в проекте не найдено. Автотесты всегда используют отдельные
БД в памяти или временном каталоге. Тестовые `CREATE TABLE` не являются миграцией
рабочей базы. Реальные пользовательские данные не затрагивались.

Одно предупреждение Starlette относится к будущему переходу TestClient с httpx
на httpx2. Предупреждение не подавлялось. Введённый диапазон FastAPI допускает
несколько версий, поэтому автоматическая замена тестового HTTP-клиента не выполнялась.

Процент покрытия не учитывает дочерний процесс smoke-теста, из-за чего CLI-модуль
отображается как непокрытый, хотя его запуск проверен. Браузерный JavaScript,
нагрузочные сценарии и PostgreSQL не проверялись. Результаты относятся к указанному
окружению и не означают доказательства отсутствия всех ошибок.

## Исправление первого запуска без базы

Ошибка `500` на `/api/projects` воспроизведена при отсутствии `instance/`:
SQLite возвращал `unable to open database file`. Добавлена явная команда `init-db`
для нового SQLite-файла и шесть регрессионных проверок в `tests/test_initialization.py`:
первое создание проекта, отказ менять существующую БД (включая пустые файлы),
отказ от неподдерживаемых подключений и запуск команды из другого каталога.
Для пользовательского запуска создана новая база `instance/requirements_trace.db`.
Существующие данные и схемы не мигрировались.
