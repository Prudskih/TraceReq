# TraceReq

Веб-приложение на FastAPI для управления проектами, требованиями, историей изменений
и матрицей трассировки. Поддерживает импорт DOCX и экспорт XLSX.

## Установка и запуск

Нужен Python 3.11 или новее. Из корня репозитория:

```bash
python -m venv .venv
# Windows PowerShell:
.venv\Scripts\Activate.ps1
# Linux/macOS:
# source .venv/bin/activate
python -m pip install -e .
python -m tracereq
```

Или `python run_app.py`: скрипт создаёт `.venv`, устанавливает пакет и запускает сервер.
Существующее окружение должно использовать Python 3.11+.
Сохранён запуск `python app.py` после установки пакета.
`python -m pip install -r requirements.txt` устанавливает тот же пакет из корня проекта.

ASGI-запуск:

```bash
python -m uvicorn tracereq.web.app:create_app --factory --host 127.0.0.1 --port 5000
```

Также сохранена точка входа `app:app` для Uvicorn.
После установки доступна команда `tracereq`.

- Приложение: <http://127.0.0.1:5000>
- Swagger UI: <http://127.0.0.1:5000/docs>
- ReDoc: <http://127.0.0.1:5000/redoc>
- OpenAPI: <http://127.0.0.1:5000/openapi.json>

### Существующая база данных

Запуск рассчитан на готовую базу с таблицами `projects`, `requirements`, `links`,
`requirement_history` и существующим полем `requirements.project_id`.
Приложение не создаёт таблицы, не запускает миграции и не исправляет старые данные.
Если базы ещё нет, перед первым запуском выполните:

```powershell
.\.venv-test\Scripts\python.exe -m tracereq init-db
```

В другом активированном окружении: `python -m tracereq init-db`.
Команда создаёт папку и таблицы новой SQLite-базы по настройкам. Если файл уже
существует, команда отказывается менять его, даже если он пустой. Это инициализация
новой базы, а не миграция. После неё запустите сервер обычной командой.

При запуске из исходников сохранён путь `instance/requirements_trace.db` в корне проекта.
При установке wheel расположение по умолчанию — `instance/` в рабочем каталоге процесса.
Для развёртывания задайте абсолютный `INSTANCE_DIR` или абсолютный SQLite URL.
Папка и файл существующей БД не переносятся вместе с Python-пакетом.

## Конфигурация

Настройки описаны в `src/tracereq/settings.py`. Переменные окружения имеют приоритет
над `.env` в рабочем каталоге. Пример — `.env.example`.

- `DATABASE_URL`: по умолчанию `sqlite:///requirements_trace.db`.
- `INSTANCE_DIR`: база для относительных SQLite-путей.
- `HOST`: `127.0.0.1` для встроенной команды запуска.
- `PORT`: `5000` для встроенной команды запуска.
- `MAX_UPLOAD_BYTES`: `10485760`, предел содержимого DOCX, читаемого приложением.
- `REQUIREMENT_TYPE_ALIASES`: необязательный JSON-словарь заголовков DOCX и типов требований.

Для внешнего запуска Uvicorn адрес и порт задаются его собственными аргументами.
Для PostgreSQL или другой СУБД нужен соответствующий драйвер SQLAlchemy.

## Структура и зависимости

Код находится в устанавливаемом пакете `src/tracereq`:

- `domain/`: перечисления, независимые снимки сущностей, прикладные ошибки.
- `application/commands.py`: валидируемые входные команды Pydantic.
- `application/ports.py`: небольшие протоколы репозиториев, Unit of Work, парсера и экспортёра.
- `application/projects.py`, `requirements.py`, `links.py`: сценарии работы с данными.
- `application/importing.py`, `reporting.py`: пакетный импорт, матрица и экспорт.
- `infrastructure/persistence/`: SQLAlchemy-модели, преобразования, репозитории, транзакции.
- `infrastructure/documents/`: конкретные адаптеры DOCX и XLSX.
- `web/routers/`: отдельные маршруты проектов, требований, связей, документов и страниц.
- `web/schemas.py`, `errors.py`: контракты ответов и централизованная обработка ошибок.
- `web/dependencies.py`, `app.py`: связывание зависимостей и фабрика приложения.
- `web/templates/`, `web/static/`: включённые в пакет ресурсы интерфейса.

Домен не импортирует сторонние библиотеки. Прикладной слой зависит от домена,
протоколов и Pydantic; он не импортирует FastAPI, SQLAlchemy или файловые библиотеки.
Инфраструктура реализует протоколы. Конкретные зависимости собираются на границе приложения.

Синхронные обработчики выполняются FastAPI в пуле потоков: синхронные SQLAlchemy,
python-docx и openpyxl не вызываются из асинхронных обработчиков запросов.
Одна сессия используется последовательно в рамках одного запроса.

## Транзакции и история

Репозитории выполняют `flush`, но не `commit`. Прикладной сценарий фиксирует операцию
через Unit of Work; при ошибке незавершённая транзакция откатывается, сессия закрывается.
Создание/изменение требования и запись истории выполняются в одной транзакции.
Весь импорт DOCX фиксируется одним `commit`.

При удалении требования удаляются его связи и история. При удалении проекта это
выполняется для всех его требований в общей транзакции. Новая запись `DELETE` не создаётся:
существующий внешний ключ истории требует живое требование. `deleted_by` принимается
для совместимости и записывается в серверный лог; это не постоянный аудиторский журнал.
Независимый аудит удалений требует отдельного решения по схеме данных.
SQLite-соединения включают проверку внешних ключей; существующие данные автоматически
не исправляются. Имена таблиц, столбцов и сохраняемые имена Enum не изменены.

## REST API

Базовый префикс `/api`. Прежние URL сохранены.

Проекты:

- `GET /projects`
- `POST /projects`
- `PUT /projects/{project_id}`
- `DELETE /projects/{project_id}`

Требования:

- `GET /projects/{project_id}/requirements`
- `POST /projects/{project_id}/requirements`
- `GET /projects/{project_id}/requirements/{requirement_id}`
- `PUT /projects/{project_id}/requirements/{requirement_id}`
- `DELETE /projects/{project_id}/requirements/{requirement_id}`
- `GET /projects/{project_id}/requirements/{requirement_id}/history`

Связи и документы:

- `POST /projects/{project_id}/links`
- `DELETE /links/{link_id}`
- `GET /projects/{project_id}/matrix`
- `POST /projects/{project_id}/requirements/import/docx` — multipart-поле `file`.
- `GET /projects/{project_id}/export`
- `GET /projects/{project_id}/export/matrix`

Создание возвращает `201`. Ошибки имеют форму `{"error": "..."}`:
`400` - нарушение прикладного правила или некорректный документ;
`404` - сущность не найдена; `409` — конфликт ограничений БД;
`422` - нарушение схемы входных данных; `500` — непредвиденная ошибка.
SQL и внутренние исключения не возвращаются клиенту.

Изменения контракта относительно старой реализации:

- Пустые названия, недопустимые Enum, превышение длины и неизвестные поля отклоняются.
- Явный `null` для изменяемого поля отклоняется; пропущенное поле при `PUT` сохраняется.
- Списки, матрица, импорт и экспорт несуществующего проекта возвращают `404`.
- При создании требования проверяется существование проекта.
- Формат дат проектов сохранён как HTTP-date; даты требований и истории — ISO 8601.
